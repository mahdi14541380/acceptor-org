# Acceptor_org — سایت فروش خدمات تلگرام

## چندزبانگی

سایت الان ۴ زبانه: انگلیسی (`/en`)، روسی (`/ru`)، چینی (`/zh`)، عربی (`/ar` — راست‌به‌چپ خودکار).

- هر آدرس با پیشوند زبان شروع میشه، مثلاً `acceptororg.com/ru/pricing`
- وقتی کسی بدون پیشوند وارد بشه (مثلاً فقط `acceptororg.com`)، خودکار بر اساس زبان مرورگرش به یکی از این ۴ زبان هدایت میشه
- متن‌های هر زبان تو `lib/i18n/dictionaries/en.json` (و ru/zh/ar) هستن — برای تغییر متن‌ها همون فایل JSON مربوط به زبان رو ویرایش کن
- **نکته مهم:** اسم و توضیح خدمات داخل `lib/data.ts` (بخش "Other Telegram services") و اسم کشورها تو `lib/countries.ts` فعلاً فقط انگلیسی هستن و ترجمه نشدن — چون این‌ها دیتای متغیر هستن نه متن ثابت صفحه. اگه خواستی این‌ها هم چندزبانه بشن بگو تا ساختارش رو عوض کنم.
- اگه بعداً زبان پنجم یا بیشتر خواستی، فقط کافیه یه فایل دیکشنری جدید بسازی و بهش تو `lib/i18n/locales.ts` اضافه کنی.

## راه‌اندازی بک‌اند (حساب کاربری، موجودی، خرید واقعی)

سایت الان این قابلیت‌ها رو داره: ثبت‌نام/ورود، پنل کاربری با موجودی، شارژ با تتر (شبکه ترون)، خرید استارز از موجودی، و پنل ادمین برای تغییر قیمت‌ها. برای فعال شدنشون باید ۳ سرویس رو وصل کنی:

### ۱. Supabase (دیتابیس + احراز هویت) — رایگان

1. برو [supabase.com](https://supabase.com) → ثبت‌نام → **New Project**
2. بعد از ساخته شدن پروژه، برو **SQL Editor** → **New query** → کل محتوای فایل `supabase/schema.sql` (تو همین پروژه) رو کپی/پیست کن → **Run**. این کار همه‌ی جدول‌های لازم (کاربران، موجودی، سفارش‌ها، قیمت‌ها) رو می‌سازه.
3. برو **Settings → API** و این ۳ مقدار رو بردار:
   - `Project URL` → میره تو `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → میره تو `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key (⚠️ خیلی حساسه، هیچ‌جا جز تنظیمات سرور نذارش) → میره تو `SUPABASE_SERVICE_ROLE_KEY`
4. اگه می‌خوای ایمیل تایید ثبت‌نام قشنگ‌تر بشه: **Authentication → Email Templates**

### ۲. darimarket.online (شارژ تتر + خرید استارز — همه با یه API key)

کلید API که دادی رو تو `DARIMARKET_API_KEY` بذار. سایت الان برای هر دو کار از همین API استفاده می‌کنه:
- شارژ حساب کاربر: `POST /v1/topup/usdt` یه آدرس واریز می‌سازه، کاربر تتر (شبکه TRC20 یا BEP20) میفرسته، سایت با `GET /v1/topup/usdt/{deposit_id}` هر ۸ ثانیه وضعیت رو چک می‌کنه و وقتی تایید شد موجودی خودکار شارژ میشه (چون این API وب‌هوک نداره، فقط Polling)
- خرید استارز: `POST /v1/buy` — الان دقیقاً طبق مستندات واقعی‌ست:
  - `product_id` به‌ازای هر کشور با `GET /v1/products?kind=api_country&q=<اسم کشور>` پیدا میشه
  - `quantity` = تعداد استارزی که مشتری می‌خواد (نه تعداد سفارش)
  - `items` = `[اسم کشور]` (طبق تاییدت — نه یوزرنیم گیرنده)
  - قیمت هر کشور تو `lib/countries.ts` الان **قیمت هر ۱ استارزه**؛ مبلغ نهایی = قیمت × تعداد
  - چون async هست، سایت هر ۶ ثانیه `GET /v1/orders/{order_id}` رو چک می‌کنه تا `download` (رسید/تاییدیه) آماده بشه

**نکته‌ی مهم معماری:** `POST /v1/buy` هیچ فیلدی برای «یوزرنیم گیرنده‌ی نهایی» نداره — فقط تامین عمده‌ی استارز با نرخ اون کشوره. یوزرنیم تلگرام مشتری رو تو دیتابیس خودمون (`orders.telegram_username`) ذخیره می‌کنیم برای رکورد، ولی **تحویل نهایی استارز به اکانت مشتری هنوز به این سیستم وصل نیست** — باید بگی این مرحله چطور باید انجام بشه (دستی خودت انجامش میدی؟ یا یه API دیگه هست که باید بهش وصل بشیم؟) تا اون بخش رو هم تکمیل کنم.

### ۳. تنظیم متغیرهای محیطی

- **محلی (رو سیستم خودت):** فایل `.env.example` رو کپی کن به اسم `.env.local` و مقدارها رو پر کن
- **رو Vercel:** پروژه → **Settings → Environment Variables** → همون کلیدها رو یکی‌یکی اضافه کن (دقیقاً همون اسم‌ها) → بعد از اضافه کردن، یه بار **Redeploy** بزن

### ۴. ادمین شدن

ایمیل ادمین از env variable میاد، نه از کد. تو `.env.local` (و تو Vercel) این رو بذار:
```
ADMIN_EMAIL=sadboy1454@gmail.com
```
بعد با همین ایمیل تو سایت ثبت‌نام/لاگین کن، برو به آدرس `/en/admin` (یا `/fa/admin` و غیره) — پنل تغییر قیمت کشورها رو می‌بینی.

### امنیت — مهم
- **هیچ‌وقت** `SUPABASE_SERVICE_ROLE_KEY` یا `DARIMARKET_API_KEY` رو تو کد پابلیک یا چت جایی نذار؛ این‌ها فقط تو Environment Variables سرور باید باشن.
- کلید API که قبلاً برام فرستادی رو (`rz_rirP4s0XE4V8DlqAHrU36TvyTfGjNR54`) باید تو پنل darimarket **Revoke** کنی و یه کلید تازه بسازی، چون یه بار به‌صورت متن ساده جایی نوشته شده.

## دانلود رسید (نکته‌ی مهم امنیتی)

`GET /dl/{token}` تو darimarket نیاز به همون کلید API سرور داره (`X-Api-Key`) — یعنی نمیشه لینکش رو مستقیم به مرورگر مشتری داد چون کلید API ما رو نداره و 401 می‌گیره. برای همین یه مسیر پراکسی ساختم:

`GET /api/downloads/{token}` روی سرور خودمون → چک می‌کنه اون توکن واقعاً مال سفارش همون کاربره → بعد با کلید API از darimarket می‌گیرتش و مستقیم به مرورگر مشتری تحویل میده (کلید API هیچ‌وقت به مرورگر لو نمیره).

**نکته:** طبق مستندات، این توکن‌ها `expires_at` و ظاهراً محدودیت تعداد دانلود هم دارن (`410 Expired or download limit`). اگه مشتری چندبار رو دکمه‌ی دانلود کلیک کنه، هر بار یه درخواست جدید به darimarket میره و ممکنه به اون محدودیت بخوره. اگه لازم شد میشه فایل رو یه‌بار گرفت و ذخیره کرد (مثلاً تو Supabase Storage) تا دانلودهای بعدی از سرور خودمون باشه نه از darimarket — بگو اگه این رو هم بسازم.

## قیمت دو‌گانه (اکانت قدیمی / جدید)

هر کشور الان ۲ قیمته:
- **قدیمی (Old):** فیلد `price` تو `lib/countries.ts` — تحویل سریع‌تر
- **جدید (New):** فیلد `priceNew` تو `lib/countries.ts` — تحویل کندتر

هر دو رو می‌تونی از پنل ادمین (`/admin`) جدا از هم ویرایش کنی. مشتری هم موقع خرید تو `/account` انتخاب می‌کنه کدوم نوع رو می‌خواد. سفارش واقعی هم به‌درستی به darimarket وصل شده: قدیمی → `kind=aged`، جدید → `kind=api_country`.

## تاریخچه‌ی پرداخت‌ها

تو `/account`، زیر فرم شارژ، یه بخش «تاریخچه‌ی پرداخت‌ها» هست که همه‌ی شارژهای قبلی (و در حال انتظار) رو از دیتابیس می‌خونه — پس با رفرش کردن صفحه گم نمیشه. اگه یه شارژ هنوز `pending` باشه، آدرس واریزش همونجا دوباره نمایش داده میشه تا بتونی کامل پرداخت کنی.

**نکته‌ی مهم:** چون darimarket برای شارژ وب‌هوک نداره (فقط Polling)، تاییدشدن پرداخت فقط وقتی تو دیتابیس ما ثبت میشه که یکی واقعاً وضعیتش رو چک کنه. اگه تب مرورگر رو ببندی قبل از این‌که Poll خودکار (هر ۸ ثانیه، فقط تو همون لحظه‌ی ساخت شارژ) تموم بشه، حتی اگه darimarket پرداخت رو تایید کرده باشه، موجودی سایت شارژ نمیشه تا یکی دوباره چکش کنه. برای همین:
- هر بار صفحه‌ی `/account` باز میشه، خودکار همه‌ی شارژهای `pending`/`review` رو یه‌بار چک می‌کنه
- کنار هر پرداخت در انتظار یه دکمه‌ی `↻` هست که می‌تونی دستی دوباره چکش کنی

اگه بخوای این کاملاً خودکار و بدون نیاز به باز کردن صفحه باشه (مثلاً هر چند دقیقه سرور خودش چک کنه)، باید یه **Vercel Cron Job** اضافه کنیم که هر چند دقیقه یه‌بار همه‌ی شارژهای در انتظار رو خودش چک کنه — بگو اگه بخوای اینم بسازم.

## ساختار پروژه

- `app/` — صفحات سایت (Home, Services, Pricing, About, Contact)
- `components/` — Nav، Footer، و کامپوننت Tick (المان امضادار برند)
- `lib/data.ts` — **تنها فایلی که برای اضافه/ویرایش/حذف خدمات و قیمت‌ها لازمه ویرایش کنی**
- `public/logo.jpg` — لوگوی آپلودی‌ت (فعلاً در نویگیشن استفاده نشده، فقط متن؛ اگه خواستی لوگوی تصویری رو جایگزین متن کنیم بگو)

## اضافه کردن یا تغییر قیمت خدمات

- **استارز تلگرام (قیمت به تفکیک کشور):** فایل `lib/countries.ts` رو ویرایش کن. هر کشور داخل قاره‌ی خودش با پرچم، کد تلفن و قیمت مشخص شده. برای آفریقا، آمریکای جنوبی و اقیانوسیه فعلاً `countries: null` گذاشته شده (یعنی "به‌زودی")؛ هروقت لیست قیمت اون قاره‌ها رو داشتی، `null` رو با آرایه‌ی کشورها جایگزین کن.
- **بقیه خدمات (مثل ایموجی پک، بوست کانال):** فایل `lib/data.ts` رو ویرایش کن.

پریمیوم فعلاً از سایت حذف شده چون فروش نداری؛ هروقت خواستی برگردونیش بگو تا اضافه کنم.

## سئو (SEO)

- تگ‌های title/description/keywords برای عبارت‌هایی مثل "buy telegram stars" تنظیم شده
- `app/sitemap.ts` و `app/robots.ts` خودکار sitemap.xml و robots.txt می‌سازن
- صفحه `/pricing/stars` دارای FAQ + داده‌ی ساختاریافته (Schema.org FAQPage) برای نمایش بهتر تو نتایج گوگله
- برای رتبه گرفتن واقعی رو "buy stars telegram"، بعد از دیپلوی باید سایت رو تو **Google Search Console** ثبت کنی و sitemap رو submit کنی؛ رتبه گرفتن چند هفته تا چند ماه طول می‌کشه و به بک‌لینک و محتوا هم بستگی داره — این یه پروسه‌ست، نه چیزی که فقط با کد حل بشه.

## دیپلوی روی Vercel

1. پروژه رو به یه ریپازیتوری گیت‌هاب پوش کن
2. تو vercel.com ریپو رو وارد کن (import) — Vercel خودش Next.js رو تشخیص میده
3. دامنه `acceptororg.com` رو از تنظیمات پروژه به Vercel وصل کن (Vercel یه سری رکورد DNS بهت میده که باید تو پنل دامنه‌ت ثبت کنی)
